# A39 GET /api/kitchen/events

状态：API和Web已实现；真实HTTP及专用临时PostgreSQL验证通过，平板/Tailnet HTTPS链路仍待验收。调用方仅[S06厨房屏](../screens/S06_KITCHEN_DISPLAY.md)，手机不订阅。

## 请求与认证

使用现有HttpOnly设备会话Cookie，不接受Body或Query，也不接收userId、token或设备ID。认证失败沿用401错误envelope，非法Query返回400。每个账号在单个API进程中最多6条连接，超过返回429 `KITCHEN_CONNECTION_LIMIT`。

成功200，响应为`text/event-stream; charset=utf-8`，`Cache-Control: no-store, no-transform`、`X-Accel-Buffering: no`。发送前保留认证钩子设置的Cookie；不使用Service Worker缓存或WebSocket。

## 事件Contract

每帧为`data: <JSON>\n\n`，shared导出`KitchenEventSchema` / `KitchenEvent`：

| type        | 含义                           | 客户端行为                                |
| ----------- | ------------------------------ | ----------------------------------------- |
| `ready`     | 已订阅当前登录账号             | 立即GET A10，补齐断线或建立连接期间的变化 |
| `changed`   | 当前账号的厨房或菜谱写入已成功 | 重新GET A10，不将通知本身当作业务成功回执 |
| `heartbeat` | 连接存活，每30秒一次           | 仅更新连接存活期限，不查询业务API         |
| `reconnect` | 定期重新验证会话               | 平滑重建连接，成功时不显示断线提示        |

只接受严格对象`{type:"ready"|"changed"|"heartbeat"|"reconnect"}`，不携带菜谱、用户信息或凭据，不重放历史事件。初始读取、每次重连后A10的完整快照负责最终收敛。

## 通知边界与生命周期

成功的厨房替换/切菜/清空/完成和菜谱新增/编辑/删除/正式导入，在HTTP成功响应后通知同一账号；错误/回滚、读取、预校验和爱心偏好不通知。采用进程内订阅集合，不增加数据库表、轮询查询、Redis或第三方依赖。适用于当前单API实例；不能直接用于多进程/多实例或绕过API的数据库写入。如需扩容，先增加跨实例事件源，不得将本实现当作分布式通知。

每30秒的心跳不访问数据库；连接最长5分钟，之后正常结束，客户端重连时通过既有认证钩子重新验证会话。退出/切换账号成功后结束该原会话的连接。客户端断开、响应错误或写入背压时清理连接；API关闭前结束所有流和定时器，防止长连接阻塞退出。

## Web降级

健康连接时停止定时A10读取；收到变化通知才读完整快照。连续通知在已有读请求/写操作期间合并，避免并发GET与旧响应覆盖。读取失败即使SSE仍连接，也恢复定时重试；成功后再次停止定时检查。

断流、无效事件或75秒未收到消息时关闭原连接，显示“实时连接暂不可用，正在定时检查菜单”，10秒后重连，期间沿用A10的`pollIntervalSeconds`串行检查。浏览器无EventSource能力时同样降级。不在后台重连或轮询；回前台/恢复页面立即重建连接和读A10，离开页面关闭连接、看门狗和重试定时器。

已有错误说明、滚动位置、目标份数、版本冲突和完成回执规则保持不变。SSE通知不自动跳转、弹庆祝提示或触发写入。

## 验收

权限与Query隔离、账号通知隔离、仅成功写入通知、菜谱删除/导入覆盖、心跳零业务查询、连接上限/注销/关闭清理；Web健康60秒无定时GET、通知读取、断流回退/重连补读、75秒失活检测、无EventSource降级、通知合并、读失败恢复及后台断开。
