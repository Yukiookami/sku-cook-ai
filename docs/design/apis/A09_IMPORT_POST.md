# A09 POST /api/recipes/import

状态：源码已实现；初始迁移已应用于本地开发数据库；A09批量写入与事务回滚尚未通过真实HTTP验收。调用方：[S05](../screens/S05_RECIPE_IMPORT.md)。与[A08](A08_IMPORT_VALIDATE_POST.md)相同Body、大小限制、错误报告格式；校验函数复用，不复制一套字段规则。

## 成功201

```json
{ "importedCount": 3, "recipeIds": [101, 102, 103] }
```

recipeIds按输入顺序，计数与长度一致；只在整批提交成功后返回。没有跳过重复、部分成功、导入图片或自动发送厨房。

## 处理

1. 检查JSON、version、最多1000条、最多10MiB、每条字段与文件内部同名。
2. 事务内再次检查默认用户现有同名；不能信任先前A08成功，客户端可直接调用本API。
3. 全部通过，事务创建菜谱和从属数据；servings/scaleWithServings省略分别默认1/true，显式值保留，amount按原份数原文写入，不预先换算；最终数据库唯一约束防其他并发请求。
4. 提交成功才返回201。任一失败整体回滚，包括已分配但未提交的id和子数据；数据库序列允许有空洞，不伪造连续id。

并发唯一约束冲突导致回滚后重新只读确认冲突条目并返回422报告；若无法识别为预期冲突则500并记录日志，不把所有异常包装成“同名”。事务超时为60秒以容纳最多1000条菜谱，不在事务中做外部网络请求。

## 错误

422 IMPORT_VALIDATION_FAILED（全部可识别条目问题，同名也使用导入报告）；400 JSON格式；413大小；500/503通用。失败不返回importedCount=0的成功形状。

## 重试与测试

客户端提交中防重复；本API不实现幂等token。提交后响应丢失可能已经成功，再次提交将触发同名422，应让用户先查列表，不能自动重试。

测试正常顺序与计数、最后一条故意失败前999条不入库、子数据错误回滚、预校验后别人创建同名、并发导入同文件仅一批成功、直接未预校验提交、默认用户隔离、版本与大小限制。
