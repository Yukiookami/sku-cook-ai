# S07 发送 / 查看厨房菜单弹层设计书

状态：Web弹层已实现；A10/A11/A13 API client已按shared Contract接入，读状态、版本写入、清空均使用服务端响应。独立临时PostgreSQL已通过A11真实HTTP发送、持久化、同账号第二设备读取与409拒绝测试；浏览器已验证实际发送后的成功弹窗及厨房内容显示，真机与A13业务验收仍待做。不是独立路由；S01 多选发送、S02 单道发送与“查看厨房菜单”共用。组件 `KitchenMenuPanel.vue`。

## 1. 布局与模式

V2采购增量：发送模式的“本次选择”新增采购入口，携带已独立调整的目标份数；已成功读取且非空的“厨房当前菜单”另有采购入口，携带服务端菜单份数。两者打开[S14](S14_SHOPPING_PANEL.md)，不替换/清空厨房、不记录历史；未知厨房状态时不可基于旧菜单创建预览。

手机 Vant 底部 Popup，最大高度约视口85%，内部可滚动；平板可中宽弹窗。顶栏标题与关闭按钮，底部固定操作区。

| 模式   | 主体                                          | 操作                                   |
| ------ | --------------------------------------------- | -------------------------------------- |
| 发送   | “本次选择（N道）”按顺序列名；“厨房当前菜单”区 | 空菜单：发送到厨房；非空：替换厨房菜单 |
| 仅查看 | “厨房当前菜单”，当前菜明确标“当前查看”        | 关闭；有菜单时次级“清空厨房”           |

发送模式可取消、关闭而保留列表选择；不在弹层重新排序，新菜单顺序就是勾选顺序。当前厨房菜单是打开时读取的快照，不宣称实时在线或设备已收到。“当前查看”不是“已完成/剩余进度”。

“本次选择”每道菜有独立“− / N人份 / ＋”。详情进入带当前目标份数，列表进入默认该菜原份数（来自列表摘要），不得所有菜自动变成1人份；原份数说明显示在旁。仅查看模式显示已发送的目标份数但不提供调整按钮；目标不得低于1。

## 2. API 与交互

打开立即 [A10](../apis/A10_KITCHEN_GET.md)，手机不定时刷新；关闭后清理请求。失败保留本次选择，显示重试，禁止在未知状态发送，以免无意覆盖。空菜单文字“厨房当前没有菜单”。

发送携带读取的 expectedRevision 调 [A11](../apis/A11_KITCHEN_PUT.md)。已有菜单时主按钮明确“替换厨房菜单”，上方说明“将替换当前的 N 道菜”；这是显式确认，不再叠加模态弹窗。成功说明厨房屏将在下次读取时更新，不提示“厨房设备已收到”。不会自动唤醒熄屏平板。

发送中仅主按钮显示“正在发送…”并禁用重复提交和关闭，不在按钮外重复显示发送中文字。仅在A11成功响应后切换为居中成功弹窗，明确显示“已发送到厨房”、“已保存 N 道菜到厨房菜单。”，并说明“厨房屏保持打开并登录同一账号，将在下次读取时更新（通常 10 秒内）。”。提供“完成”（关闭弹窗并留在发送前的页面）和“返回菜谱一览”（关闭弹窗并导航至`/recipes`）两个操作。请求中、失败或409冲突时不显示成功状态。

Body为items数组，每项recipeId与targetServings，不传计算后的amount；版本冲突刷新当前菜单但保留本次各菜目标，不把刷新结果覆盖成新选择份数。

409：重新读当前菜单，显示“厨房菜单已变更，已读取最新菜单；请确认后再次发送，本次选择和份数已保留”。读取成功后主按钮改为“确认并发送到厨房”；用户再次点击才使用新revision提交，不自动提交第二次。若重新读取失败，保留读取错误和重试入口，读取成功后仍要求显式确认。服务端404缺少菜谱时说明已选菜被删除，回列表修正。

仅HTTP 409作为版本冲突，不根据错误文案推断。网络超时或断网显示“发送结果暂未确认”，保留选择与份数，提供“重新读取厨房菜单”核对结果；完成读取前禁用发送，不自动重发。其他服务端错误保留其失败说明，不伪装为冲突或成功。

“清空厨房”使用[COMMON](../COMMON.md)的 Memo 共用确认组件二次确认“清空后厨房屏将回到待机，不会记录做过；菜谱和已有历史不会删除”，确认期间锁定关闭和重复写入，保留所确认的版本；取消不请求。[A13](../apis/A13_KITCHEN_DELETE.md)成功后仅更新此弹层为空；结果不确定GET核对，不能当成功。厨房完成才通过A15记录历史，手机清空不是完成。

厨房完成后手机无通知。已经打开的弹层可以保留旧快照直至重开 / 用户点重试；提交带版本可防止旧快照误操作。关闭再开即可读新状态，不新增常驻同步逻辑。

## 4. 验收

单道/多道弹层复用；开一次只读一次（手动重试除外）；现有菜单替换明确；断网不能盲发；清空不删菜谱；完成无手机通知；冲突不自动覆写。

每道目标份数独立发送/显示；取消和冲突保留选择值；厨房清空后不修改原菜谱份数。
