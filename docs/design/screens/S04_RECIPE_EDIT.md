# S04 编辑菜谱设计书

状态：Web画面已实现；A04/A06与标签建议A03 API client已按shared Contract接入，表单复用shared输入Schema。尚未在可用服务/数据库环境执行真实HTTP业务验收。路由 `/recipes/:id/edit`，组件 `RecipeEditView.vue`；表单复用 [S03](S03_RECIPE_CREATE.md)，不要复制一套校验或输入组件。

## 1. 进入与布局

从详情“编辑菜谱”进入。[A04](../apis/A04_RECIPE_GET.md) 成功后将响应映射为表单：null → 空输入，数组顺序保留。加载期间不显示可提交的空表单；失败显示重试；404 显示“菜谱不存在 / 返回菜谱”。

标题“编辑菜谱”，底部“保存修改”，字段、分组、动态列表与新增完全相同。不能编辑 id、userId 或时间戳；没有图片。已加载但未改动时按钮禁用，改变后启用。

原份数与每条scaleWithServings从GET回填并显式提交，不用默认1/true覆盖旧值。改原份数不自动调整原量，提示核对用量；不能把详情当前目标份数/计算量回填成原菜谱。若在厨房菜单中，原量更新后目标份数仍保留并重新计算。

## 2. 保存与退出

[A06](../apis/A06_RECIPE_PUT.md) 为全量替换，不是局部合并：清空 tips、来源、时间等要按共通输入约定省略，对应服务端清除字段。不能直接将含 null 和生成字段的 GET 响应作为请求体。

成功回详情并重新读取；失败保留修改、允许重试；404 说明编辑时菜谱已删除，不创建新菜；同名 409 定位菜名。普通菜谱编辑采用最后一次成功保存为准，不假设多端协作或自动合并。离开有改动时确认，取消返回详情；网络结果不确定先读详情核对。

## 4. 验收

GET→表单→PUT 映射不泄漏生成字段；清空可选字段真能清除；删行重排持久化；与新增共用样式和校验；保存失败不丢修改。
