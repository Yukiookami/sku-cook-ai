# S02 菜谱详情设计书

状态：待实现。路由 `/recipes/:id`，组件 `RecipeDetailView.vue`；来自列表或直接链接。

## 1. 布局

顶部“返回 / 菜谱详情 / 更多”；主体顺序：菜名 → description → 人数、准备/烹饪时间、难度 → tags → 食材分组 → 编号步骤 → tips → source。底部固定主按钮“发送到厨房”，留足底部空间不挡正文。食材数量和单位靠右，note 使用辅助文字；默认组显示“食材”，其他组如“腌料”单独小标题。

没有可选字段时省略对应区块，不出现“undefined”、空标签、0 人份；时间缺失规则见 [共通设计](../COMMON.md)。长正文正常滚动，不按厨房逻辑分页。平板可食材 / 步骤两栏，但保留阅读顺序。

## 2. 行为与 API

- 原菜谱份数始终显示；用“− / 目标 N 人份 / ＋”调整本次份数，普通入口初始为原份数，最小1；[S08历史](S08_COOKING_HISTORY.md)入口可初始化为当次记录份数，入口值按shared约束校验，不覆盖Recipe原份数。纯数字且允许换算的amount按COMMON规则更新为参考用量，不调用保存API、不改变原菜谱。文字量/范围/分数与关闭换算项保持原量并提示按需调整；步骤与时间不变，不长期保存详情局部目标。
- 加载 [A04](../apis/A04_RECIPE_GET.md)；非法 id 不发业务请求，显示“菜谱不存在 / 返回菜谱”；404 同态，网络 / 500 失败则可重试，不能误报不存在。
- “更多”内“编辑菜谱”跳 S04、“删除菜谱”打开确认：“删除「番茄炒蛋」？食材和步骤也会删除；若在厨房菜单中，也会移除。”取消为默认安全操作。
- 确认后 [A07](../apis/A07_RECIPE_DELETE.md)，提交中防重复；成功回列表并重读；失败保留详情。删除结果不确定先重新读取，不自动重复删除。
- “发送到厨房”打开 [S07](S07_KITCHEN_PANEL.md)，带上这1道菜及当前目标份数，不追加现有菜单；弹层明确现有菜单是否会被替换。
- “更多”增“记录做过”，确认“记录刚做过「番茄炒蛋」3人份？时间按现在保存。”，捕获当前recipeId及目标份数调用[A17](../apis/A17_COOKING_HISTORY_POST.md)。确认/提交期间暂停份数改动，取消或请求结束后恢复；请求中防连点，不能确认3份却发另一个值。不发送/清空厨房，成功提示“已记录做饭历史”，可主动去S08；不自动导航。失败保留详情，超时提示先查历史，不自动重复POST。
- 删菜谱确认另说明“已有做饭历史会保留名字和份数，但不能再打开此菜谱”；历史入口的做法为当前最新版本，不冒称当时快照。
- source 作为纯文本；有效 http / https 地址可安全打开新页，不支持任意协议，也不后台抓取。

## 4. 验收

分组、步骤顺序和可选字段正确；删除只能确认后执行且厨房联动；无录入图片入口；单道发送不会暗中追加；失败保留信息且可重试。

手动记做过的确认、目标份数、服务端当前时间、防连点与结果不明均验证；历史打开最新菜谱并沿用历史目标，普通入口仍默认原份数；删菜保留历史文字。

目标改为3人份，鸡蛋4.5个、番茄3个、盐仍适量；注明“步骤与时间沿用原菜谱”，不修改步骤文字。验收2→3→2回到原用量，无累计误差；1人份禁用减号；发送携带目标份数。
