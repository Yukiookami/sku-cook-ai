# S02 菜谱详情设计书

状态：待实现。路由 `/recipes/:id`，组件 `RecipeDetailView.vue`；来自列表或直接链接。

## 1. 布局

顶部“返回 / 菜谱详情 / 更多”；主体顺序：菜名 → description → 人数、准备/烹饪时间、难度 → tags → 食材分组 → 编号步骤 → tips → source。底部固定主按钮“发送到厨房”，留足底部空间不挡正文。食材数量和单位靠右，note 使用辅助文字；默认组显示“食材”，其他组如“腌料”单独小标题。

没有可选字段时省略对应区块，不出现“undefined”、空标签、0 人份；时间缺失规则见 [共通设计](../COMMON.md)。长正文正常滚动，不按厨房逻辑分页。平板可食材 / 步骤两栏，但保留阅读顺序。

## 2. 行为与 API

- 加载 [A04](../apis/A04_RECIPE_GET.md)；非法 id 不发业务请求，显示“菜谱不存在 / 返回菜谱”；404 同态，网络 / 500 失败则可重试，不能误报不存在。
- “更多”内“编辑菜谱”跳 S04、“删除菜谱”打开确认：“删除「番茄炒蛋」？食材和步骤也会删除；若在厨房菜单中，也会移除。”取消为默认安全操作。
- 确认后 [A07](../apis/A07_RECIPE_DELETE.md)，提交中防重复；成功回列表并重读；失败保留详情。删除结果不确定先重新读取，不自动重复删除。
- “发送到厨房”打开 [S07](S07_KITCHEN_PANEL.md)，选择就是这 1 道，不追加现有菜单；弹层明确现有菜单是否会被替换。
- source 作为纯文本；有效 http / https 地址可安全打开新页，不支持任意协议，也不后台抓取。

补充图：更多操作面板仅“编辑菜谱 / 删除菜谱”；删除二次确认保留完整联动说明；404 状态“菜谱不存在 / 返回菜谱”，不要伪造菜谱内容。

## 4. 验收

分组、步骤顺序和可选字段正确；删除只能确认后执行且厨房联动；无录入图片入口；单道发送不会暗中追加；失败保留信息且可重试。
