# S08 做饭历史设计书

状态：Web画面已实现；A16/A18 API client已按shared Contract接入，配合S02手动记录A17及S06厨房完成A15；真实HTTP业务验收待可用服务/数据库环境。路由 `/cooking-history`，组件 `CookingHistoryView.vue`；从S01“更多 → 做饭历史”进入。用于找到最近做过的菜，不是推荐历史、浏览记录、厨房实时进度或食材库存。

## 1. 信息结构

顶栏“返回 / 做饭历史”；说明“找到最近做过的菜，点菜名查看最新做法”。按做饭时间倒序展示，每次做饭一组：

- 日期时间，例如“2026年10月8日 18:30”；来源文字“厨房完成”或“手动记录”。
- 本次菜名及目标份数，按当次顺序展示；两道示例“番茄炒蛋 · 3人份”“冬瓜汤 · 1人份”。
- 每道可用菜谱有“查看做法”文字入口；该条菜谱已删则保留当时菜名/份数并标“菜谱已删除”，不提供失效跳转。
- 组内次级“删除这次记录”；不是删除菜谱或撤销完成，不画清空全部历史按钮。

手机正文16px、点击区域至少44px，奶油黄Memo顶栏/圆角白便签卡/轻虚线，与S01及COMMON同风格；每页20次记录，触底加载，家庭场景不做虚拟滚动。不新增按天统计、日历、饮食分析、导出、历史编辑或补填过去日期。

## 2. 数据与交互

- [A16](../apis/A16_COOKING_HISTORY_GET.md)读取历史；列表按 `cookedAt DESC, id DESC` 稳定排序。进入/返回时重读第一页，分页不混拼删改前后的结果；追加请求防重入、切路由忽略旧响应。
- 点击某道的“查看做法”进入S02的**最新**菜谱，不是旧快照。历史目标份数作为详情此次初始目标，原Recipe.servings仍来自A04；历史链接传入的份数须按shared目标约束校验，不用它覆盖原量。正常列表/随机入口仍默认原份数。
- 历史菜名保存的是当时名字；改名后历史不回写，详情标题可能不同，在历史说明“查看最新做法”而非冒称原版本。没有保存食材/步骤副本。
- 记录被读到后菜谱又被删除，A04照常404；保留历史记录，不伪造做法。
- 删除前确认“删除这次做饭记录？本次N道菜的记录会移除，菜谱和厨房菜单不会改变。”；[A18](../apis/A18_COOKING_HISTORY_DELETE.md)成功后重置第一页，失败保留记录/错误/重试。404说明已被删除，刷新；结果不确定先查询，不自动再次DELETE。
- S02“记录做过”通过[A17](../apis/A17_COOKING_HISTORY_POST.md)新增一条单菜历史；本页不复制录入表单。厨房[A15](../apis/A15_KITCHEN_COMPLETE_POST.md)完成才新增整顿历史，手机清空和切菜不记。
- 手机只主动打开/返回历史页时读取，不轮询、不接收厨房完成通知，不在首页弹“已记录”提醒。

## 3. 状态

初始“正在读取做饭历史”；真实空状态“还没有做饭记录”，说明“厨房点完成会自动记录，也可在菜谱详情手动记录”，按钮“去菜谱一览”。追加失败保留已有记录并“加载失败 / 重试”；首次服务失败“无法读取做饭历史 / 重试”，不能当作空历史。末页“已经到底了”；删除提交中禁止重复，正文仍可读。

## 5. 验收

0/20/21次记录与触底、同时间稳定顺序、厨房多菜分组与手动单菜、菜名快照和份数、历史入口保留目标并打开最新菜谱、已删菜谱不可点击、历史删除确认及失败保留/刷新、旧响应与重复点击、无通知/无库存推测均验证。删记录不删除菜谱、不恢复厨房；同一道菜多次做过保留多次，不按日期去重。
