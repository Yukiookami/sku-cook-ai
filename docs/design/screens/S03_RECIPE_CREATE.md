# S03 新增菜谱设计书

状态：Web画面已实现；A05与标签建议A03 API client已按shared Contract接入，表单复用shared输入Schema。尚未在可用服务/数据库环境执行真实HTTP业务验收。路由 `/recipes/new`，组件 `RecipeCreateView.vue`，与 S04 共用 `RecipeForm.vue`。表单字段精确规则见 [COMMON](../COMMON.md)。

## 1. 表单结构

共用表单按职责拆分：RecipeForm只协调草稿、校验、API读取和提交；RecipeBasicFields、RecipeTagPicker、IngredientEditor、RecipeStepsEditor分别维护局部字段交互，通过props与更新事件通信，不直接修改父级对象或自行请求API。数量与标签复用无业务依赖的AutocompleteInput；纯回填与提交映射集中在domain/recipe-form中。弹层通过显式传入的底部操作栏边界避让，不查找特定页面选择器。

| 顺序 | 区块     | 字段 / 控件                                                                 |
| ---- | -------- | --------------------------------------------------------------------------- |
| 1    | 基本信息 | 菜名必填；介绍多行；原份数默认1、可改正整数；准备分钟、烹饪分钟；难度选择   |
| 2    | 标签     | 聚焦输入框显示可搜索的已有标签列表；可选择已有项或自由输入添加，可移除 chip |
| 3    | 食材     | 初始 1 行；名称必填、数量与单位合一输入、备注、分组；随份数换算开关默认开启 |
| 4    | 步骤     | 初始 1 行；自动 order=1，多行做法；添加、上移、下移、删除                   |
| 5    | 其他     | tips 多行，source 自由文本                                                  |

手机每条食材为小分组卡，不将多个输入挤成窄横表；“名称”与合并后的“数量与单位”输入框分行，备注、分组可展开；展开不新增数据。步骤输入保持可读高度，移动按钮带文字。最后一条食材 / 步骤可清空但提交必须至少一条有效记录；不要把空行静默丢掉。页面正常滚动，底部固定“保存菜谱”。

## 2. 交互

表单只用星号标记必填字段；未标星号的字段可留空。文本长度、数字范围和数组数量限制遵循[COMMON](../COMMON.md#31-recipeinput)，提交时以shared `RecipeInputSchema`统一校验并在字段旁显示错误；首次提交校验失败后，编辑内容会实时更新错误。数量与单位使用同一个输入框。输入纯数字时在输入框下方显示可滚动的下拉联想项，如“3个”“3克”“3勺”；选择后自动拆分填入shared的amount与unit。下方另提供“适量”“少量”“大量”“少许”快捷项。也可自由输入“适量”“2～3”“2枚”等，不限于建议单位。

标签输入框聚焦后展开已有标签列表，输入文字按包含关系筛选；选择已有标签加入 chip，仍可自由输入并点击“添加”创建新标签。没有匹配项时提示可直接添加。

手机竖屏时食材标题与首个食材卡片间距收紧为8px；较宽或横屏布局保留18px间距。

可选数字空字符串转 undefined，不转 0；食材数量允许中文。移动步骤后连续重编号。提交 shared Schema 校验，字段错误就地显示、滚动聚焦第一个错误，不只弹 Toast。

原份数不可空且大于0；说明“请按原份数填写用量”，改变原份数不自动重算已填写量。每行“随份数换算”开关决定数字是否自动换算；“适量”“1/2”等即使开启也保留原文。默认创建1人份，不强制把原2人份菜谱先除以2。

[A05](../apis/A05_RECIPE_POST.md) 成功跳 `/recipes/{id}`，列表随后失效重读。保存中禁用重复提交；同名 409 在菜名下显示，其他错误保留草稿。结果不确定告知重新查询，不自动重试 POST。

返回 / 切路由时若有改动，确认“未保存内容将丢失”；刷新关闭页使用浏览器可用的离开提醒。V1 不做自动草稿保存或离线提交。表单状态页面局部，不默认放入 Pinia。

## 4. 验收

必填、数量中文、0 分钟、可选空值、步骤重排、同名、双击、离开提醒、失败保留输入均正确；新建和导入字段规则一致，不提前实现图片。

验收原份数默认1、保存原2人份不自动改量、原份数空/0拒绝、开关false保存与回填保留。
