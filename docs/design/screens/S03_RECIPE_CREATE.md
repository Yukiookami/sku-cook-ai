# S03 新增菜谱设计书

状态：待实现。路由 `/recipes/new`，组件 `RecipeCreateView.vue`，与 S04 共用 `RecipeForm.vue`。表单字段精确规则见 [COMMON](../COMMON.md)。

## 1. 表单结构

| 顺序 | 区块     | 字段 / 控件                                                 |
| ---- | -------- | ----------------------------------------------------------- |
| 1    | 基本信息 | 菜名必填；介绍多行；人数、准备分钟、烹饪分钟；难度选择      |
| 2    | 标签     | 自由输入 + 添加，可移除 chip；已有 tag 是建议，不强制选字典 |
| 3    | 食材     | 初始 1 行；名称必填、数量字符串、单位、备注、分组           |
| 4    | 步骤     | 初始 1 行；自动 order=1，多行做法；添加、上移、下移、删除   |
| 5    | 其他     | tips 多行，source 自由文本                                  |

手机每条食材为小分组卡，不将 5 个输入挤成窄横表；“名称”与“数量 / 单位”分行，备注、分组可展开；展开不新增数据。步骤输入保持可读高度，移动按钮带文字。最后一条食材 / 步骤可清空但提交必须至少一条有效记录；不要把空行静默丢掉。页面正常滚动，底部固定“保存菜谱”。

## 2. 交互

可选数字空字符串转 undefined，不转 0；食材数量允许中文。移动步骤后连续重编号。提交 shared Schema 校验，字段错误就地显示、滚动聚焦第一个错误，不只弹 Toast。

[A05](../apis/A05_RECIPE_POST.md) 成功跳 `/recipes/{id}`，列表随后失效重读。保存中禁用重复提交；同名 409 在菜名下显示，其他错误保留草稿。结果不确定告知重新查询，不自动重试 POST。

返回 / 切路由时若有改动，确认“未保存内容将丢失”；刷新关闭页使用浏览器可用的离开提醒。V1 不做自动草稿保存或离线提交。表单状态页面局部，不默认放入 Pinia。
