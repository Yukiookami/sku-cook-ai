# S13 外卖候选管理与随机推荐

状态：S01首页“自己做 / 点外卖”模式和本页管理流程已实现；A28–A33源码及shared Contract已实现。本机开发库迁移、隔离数据库/HTTP业务验收及浏览器手机视口验收通过；未做真机验收。管理路由 `/takeout`，手机优先；本页复用COMMON的奶油黄Memo卡片、表单控件、PageHeader和确认弹窗，不新增设计图或平台SDK。

## 1. 页面入口与信息结构

- S01推荐卡片在“自己做 / 点外卖”间切换，共用推荐区域，不新建首页或混合两类候选。外卖推荐池与菜谱池完全独立。
- 空外卖池首次推荐时提示“还没有外卖候选”，不另显示“添加外卖候选”按钮；首页推荐卡片下方统一的“管理外卖候选”入口和S01“更多”均可进入本页。
- 本页顶部为返回和“外卖候选”；其后是新增/编辑表单、JSON批量导入卡片和已保存候选列表。列表展示用户手填名称、可安全外开的分享链接以及编辑/删除操作。
- 首页选择“点外卖”时，页面最上方标题切换为“点什么饭”，推荐卡标题显示“今天点什么？”；模式按钮使用共用SegmentedSwitch，当前项由滑动指示条标记，系统开启减少动态效果时关闭滑动动画。选择“自己做”时分别恢复“吃什么饭”和“今天吃什么？”。
- 一般内容16px、标题24～28px、页面边距20px、纵向间距12～24px，沿用S01和COMMON，不使用单靠颜色区分状态。手机正常滚动；不新增平台徽标、菜品图片或后台链接预览。

## 2. 候选与操作

- 候选名称必填，1–100字符；链接必填，最长2048字符，只允许有效HTTP(S) URL，不允许嵌入用户名/密码。支持店铺或菜品链接，不区分类型，不抓取平台内容。
- 必填/格式校验通过shared Schema执行，错误在对应字段旁展示并关联读屏提示；不使用浏览器原生校验气泡。
- 同一用户分享URL不能重复；URL用trim后的完整字符串做相等判定，不重写查询参数/短链。不同用户之间不互相可见，也不冲突。
- 新增和编辑共用同一Contract。保存失败保留表单；删除使用COMMON共用危险确认弹窗。确认后只删除本站候选，不会影响平台内容。
- 平台链接仅用户主动点击时以新标签打开，必须使用`target="_blank"`和`rel="noopener noreferrer"`；不自动下单、付款或承诺唤起App。
- S01“换一个”只排除当前候选；其它候选等概率，允许推荐到之前出现过的项。单候选不能换时保留当前项并说明“没有其他外卖候选”，不假装出现新结果。

## 3. JSON导入

页面内置 JSON 导入/导出区，不增加一级导入页。导出时包含当前账号全部已保存候选，文件只包含可迁移的名称和链接，并沿用相同的 version 1 导入结构；ID和时间等服务端元数据不导出。结构独立于菜谱：

```json
{
  "version": 1,
  "candidates": [{ "name": "店铺名称", "url": "https://example.com/share" }]
}
```

- 支持选择JSON文件或直接粘贴JSON；可以复制格式示例交给GPT生成候选JSON后粘贴。两种输入使用相同结构和校验，均不接受菜谱导入格式。
- 输入≤10 MiB、候选1–1000项；顶层和每项均严格校验，超限、未知字段、非HTTP(S)、输入内重复URL或与已有候选重复均整批失败，不写入部分记录。
- 文件读取或粘贴通过本地校验后显示待导入数量，用户明确点击“确认导入”才提交；服务端重新校验和查重，所有新增在同一事务中提交。
- 文件语法/结构错误定位到字段；文件内重复链接本地直接指出序号；服务端反馈的既有重复链接展示问题。网络/服务端错误造成结果不确定时先重新读取候选列表，不盲目重发导入。
- 已保存候选非空且不超过1000项时可下载格式化JSON，文件可直接用于另一账号导入；超出单次导入上限时明确提示且不导出不完整文件。空候选池不提供可用导出操作。
- 不接受菜谱导入格式、不存储用户上传文件。

## 4. 加载和失败状态

- 初次请求显示“正在读取外卖候选…”，真空池显示“还没有外卖候选”；读取失败显示可读错误和重新读取操作，不能伪装为空池。
- 保存、导入期间禁用重复提交。请求不确定时先重新读取，以现有数据核对，不能把失败当成功。
- 导入文件读取失败、非JSON、格式错误、超大文件和重复项分别说明；编辑粘贴内容后旧的通过状态立即失效。服务端404表示该候选已不存在；409单项重复链接提示重新选择/编辑；422导入冲突整批拒绝；413文件/请求过大。
- 路由卸载忽略迟到GET和写请求返回，键盘和读屏可访问，危险删除保持文字提示与二次确认。
