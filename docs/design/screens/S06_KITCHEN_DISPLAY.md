# S06 厨房显示设计书

状态：待实现。路由 `/kitchen`，组件 `KitchenDisplayView.vue`；手头闲置 Android 平板。无常规导航、录入管理、滑动手势、手机通知。

## 1. 顶部与版式

顶部按菜单顺序列出菜名，当前项蜂蜜黄底、深棕文字/粗边框并标“当前”；最多 10 道时换行，空间不足由明确“展开菜单 / 收起”按钮展示，不能用横滑当唯一操作。单道只显示菜名，不显示虚构进度。

主体有菜名、人份、食材 / 步骤和 tips（有值时）。页码显示“第 X / Y 页”，这是阅读页数，不是做菜完成数。source / 介绍不挤占主要做法，可在内容末尾说明页呈现，不能将必需 tips 裁掉。

人份显示“目标3人份（原2人份）”，从session.items按recipeId取值，沿用COMMON换算规则显示参考食材量。只读份数，不增加厨房调节按钮；保留原Recipe数据以便从原量计算，不对已经换算的值再次乘倍数。文字量和不参与换算项明确保留原量；目标不同时说明“步骤与时间沿用原菜谱”，烹饪操作不能被假定为严格线性。

- 竖屏：单道短菜谱含食材、步骤、tips 能完整放下时合并一页，只留“完成”。放不下则先食材页，再步骤页，必要时 tips 续页。
- 多道或长菜谱：食材可多页，步骤按实际可用高度分页；超长单步骤可分段续页并标“步骤 02（续）”。不能固定按“3条步骤”截断或缩小字号。
- 横屏：左食材、右步骤；任一栏溢出仍需按钮续页，所有文本可达。单道两栏完整放下时只显示“完成”。
- 实际视口、文字换行、菜单行数、字号和底部安全区决定可用空间。字号默认步骤24px，布局重算保留可读位置；750×1000 仅参考，最终按真机验收。

## 2. 底部操作

全局阅读顺序为菜1的页1…末页 → 菜2… → 最后一道末页，底部最多两枚按钮，高度 ≥56px、间距 ≥16px。

| 位置                      | 左侧             | 右侧         |
| ------------------------- | ---------------- | ------------ |
| 全菜单第1页且还有本菜后页 | 不显示           | 下一页       |
| 某菜中间页                | 上一页           | 下一页       |
| 某菜末页且后面有菜        | 若有前页则上一页 | 下一道：菜名 |
| 最后一道末页              | 若有前页则上一页 | 完成         |
| 单道合并一页              | 不显示           | 完成         |

在后一道第一页点上一页，回前一道末页，必须写回当前菜。点菜单菜名跳该菜第一页。同一道内翻页不写接口；切换调用 [A12](../apis/A12_KITCHEN_ACTIVE_PATCH.md)，成功才切换当前菜，失败保留原画面。快速点击防重复。

点完成调用[A15](../apis/A15_KITCHEN_COMPLETE_POST.md)，同事务记录整顿有序菜名/目标份数并清空菜单，收到200才显示“今天的菜做完了”，3秒后待机。误点可在手机重发并在S08删除误记，不自动恢复菜单。完成按钮无需滑动或额外确认；跳到最后一道不代表此前菜已做完，完成是用户对整份菜单的显式记录。手机仅A13清空不写历史。

响应丢失显示“完成结果暂未确认，请查看做饭历史”，GET刷新菜单但空状态不是写历史成功的证据，不自动重提或庆祝；历史/清空失败必须全部回滚，页面保留失败说明。

## 3. 轮询、并发与内容更新

[A10](../apis/A10_KITCHEN_GET.md) 首次立即请求，成功后按响应间隔（默认10秒）串行轮询；后台暂停，回前台立即读取再恢复。熄屏时不保证后台轮询，不承诺手机发送能唤醒平板。

读写不能乱序覆盖：写入前取消 / 忽略旧轮询响应；版本失配重新读取并显示“厨房菜单已更新，请重新操作”。完成冲突不能清掉新菜单。读接口包含完整 recipes，菜谱内容修改也可被发现；相同内容不重置页码、DOM 或日期区域，不跑每秒时钟。

菜单成员、顺序或当前菜变化时切到当前菜第一页；仅当前菜内容修改则重算分页并保留/夹紧有效页码。只是版本变化而可见内容不变时不重绘、不重置页码。删除当前菜由后端选剩余第一道；空菜单回待机，不显示用户点击完成才有的本地庆祝文案。

目标份数变化属于可见内容变化，即使recipeIds与active不变也更新食材并重算分页。同一道原菜谱被编辑时目标仍按会话值，原份数/原量用新数据；断网保留最后成功读取的原菜谱与目标快照，不重新默认为1。

## 4. 设备与错误状态

| 状态         | 展示 / 行为                                                                             |
| ------------ | --------------------------------------------------------------------------------------- |
| 首次加载     | “正在读取厨房菜单”，无旋转动画                                                          |
| 空菜单       | 日期、“在手机上选菜后这里会显示做法”；无翻页或完成按钮                                  |
| 断网已有内容 | 保留原菜谱，文字“连接中断，显示上次内容 / 重试”；禁用服务端切换与完成，本菜本地翻页可用 |
| 首次读取失败 | “无法读取厨房菜单 / 重试”，不是空菜单                                                   |
| 写入失败     | 保留页面，明确失败 / 结果待确认；GET 后再操作                                           |
| 常亮不可用   | “无法自动保持常亮，请在系统设置中调整屏幕超时”，只显示一次，可收起，不阻塞阅读          |

有非空菜单且页面可见时申请 Screen Wake Lock；后台、空菜单、退出时释放，回前台仍有菜单时重申请。feature detection + HTTPS 条件检查；拒绝或系统释放要处理，不承诺低电量时必然常亮。页面没有能力替平板设充电上限或点亮已黑屏；Fully Kiosk 仅后续设备运维选项，不加控制 UI。

## 6. 验收

单道合并只显示完成；长食材、5000字单步骤和tips全部可读、不溢出；10道长菜名菜单占高后仍分页正确；横竖切换不丢文字。相同轮询不重绘；改菜内容能更新；旧完成不清新菜单；写入失败不显示成功。HTTPS真机常亮/释放、后台返回、低电量和不支持的浏览器均验收，手机不收到通知。
