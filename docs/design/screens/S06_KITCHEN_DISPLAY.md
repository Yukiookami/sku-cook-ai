# S06 厨房显示设计书

状态：Web画面已实现；A10/A12/A15 API client已按shared Contract接入，份数换算使用shared函数。尚未在可用服务/数据库环境执行真实HTTP业务验收；Android平板真机验收待做。路由 `/kitchen`，组件 `KitchenDisplayView.vue`；手头闲置 Android 平板。无常规导航、录入管理、滑动手势、手机通知。

## 1. 顶部与版式

顶部按菜单顺序列出菜名，当前项蜂蜜黄底、深棕文字/粗边框并标“当前”；最多 10 道时换行，空间不足由明确“展开菜单 / 收起”按钮展示，不能用横滑当唯一操作。单道只显示菜名，不显示虚构进度。

主体显示菜名、人份、食材 / 步骤和 tips（有值时）。当前只呈现一道菜，食材、步骤、tips、来源与介绍按顺序连续排布并通过页面纵向滚动阅读；不显示页码、不按屏幕高度拆分内容。source / 介绍不挤占主要做法，放在内容末尾，不能裁掉。

人份显示“目标3人份（原2人份）”，从session.items按recipeId取值，沿用COMMON换算规则显示参考食材量。只读份数，不增加厨房调节按钮；保留原Recipe数据以便从原量计算，不对已经换算的值再次乘倍数。文字量和不参与换算项明确保留原量；目标不同时说明“步骤与时间沿用原菜谱”，烹饪操作不能被假定为严格线性。

- 竖屏：食材卡片在上，步骤与补充信息依次向下排列；无论长短都自然滚动，不拆成页。
- 横屏：优先左食材、右步骤；当两栏导致内容过长时允许页面继续纵向滚动。所有文字始终可达。
- 字号默认步骤24px，保持可读位置与底部安全区；750×1000 仅参考，最终按真机验收。
- 步骤编号/标识列的外框顶部与步骤正文首行的行盒顶部对齐；正文多行时保持同一左列起点，不垂直居中编号，也不裁切或缩小字号。

## 2. 底部操作

底部最多两枚按钮，高度 ≥56px、间距 ≥16px。按钮切换的是整道菜，不是屏内分页。

| 位置       | 左侧   | 右侧         |
| ---------- | ------ | ------------ |
| 第一道菜   | 不显示 | 下一道：菜名 |
| 中间一道菜 | 上一道 | 下一道：菜名 |
| 最后一道菜 | 上一道 | 完成         |
| 仅一道菜   | 不显示 | 完成         |

通过菜单或上下道按钮切换时调用 [A12](../apis/A12_KITCHEN_ACTIVE_PATCH.md)，成功才切换当前菜，失败保留原画面。快速点击防重复。

点完成调用[A15](../apis/A15_KITCHEN_COMPLETE_POST.md)，同事务记录整顿有序菜名/目标份数并清空菜单，收到200才显示“今天的菜做完了”，3秒后待机。误点可在手机重发并在S08删除误记，不自动恢复菜单。完成按钮无需滑动或额外确认；跳到最后一道不代表此前菜已做完，完成是用户对整份菜单的显式记录。手机仅A13清空不写历史。

响应丢失显示“完成结果暂未确认，请查看做饭历史”，GET刷新菜单但空状态不是写历史成功的证据，不自动重提或庆祝；历史/清空失败必须全部回滚，页面保留失败说明。

## 3. 轮询、并发与内容更新

[A10](../apis/A10_KITCHEN_GET.md) 首次立即请求，成功后按响应间隔（默认10秒）串行轮询；后台暂停，回前台立即读取再恢复。熄屏时不保证后台轮询，不承诺手机发送能唤醒平板。

读写不能乱序覆盖：写入前取消 / 忽略旧轮询响应；版本失配重新读取并显示“厨房菜单已更新，请重新操作”。完成冲突不能清掉新菜单。读接口包含完整 recipes，菜谱内容修改也可被发现；相同内容不重置滚动位置、DOM 或日期区域，不跑每秒时钟。

菜单成员、顺序或当前菜变化时保留各菜在本次页面会话中的纵向阅读位置；首次打开新菜从顶部开始。路由离开后再回来恢复当前菜的阅读位置。只是版本变化而可见内容不变时不重绘、不重置滚动位置。删除当前菜由后端选剩余第一道；空菜单回待机，不显示用户点击完成才有的本地庆祝文案。

目标份数变化属于可见内容变化，即使recipeIds与active不变也更新食材。同一道原菜谱被编辑时目标仍按会话值，原份数/原量用新数据；断网保留最后成功读取的原菜谱与目标快照，不重新默认为1。

## 4. 设备与错误状态

| 状态         | 展示 / 行为                                                                              |
| ------------ | ---------------------------------------------------------------------------------------- |
| 首次加载     | “正在读取厨房菜单”，无旋转动画                                                           |
| 空菜单       | 日期、“在手机上选菜后这里会显示做法”；无翻页或完成按钮                                   |
| 断网已有内容 | 保留原菜谱，文字“连接中断，显示上次内容 / 重试”；禁用服务端切换与完成，本菜本地翻页可用  |
| 首次读取失败 | “无法读取厨房菜单 / 重试”，不是空菜单                                                    |
| 写入失败     | 保留页面，明确失败 / 结果待确认；GET 后再操作                                            |
| 常亮不可用   | “无法自动保持常亮，请在系统设置中调整屏幕超时”，用户收起后记住该选择，后续访问不重复打扰 |

有非空菜单且页面可见时申请 Screen Wake Lock；后台、空菜单、退出时释放，回前台仍有菜单时重申请。feature detection + HTTPS 条件检查；拒绝或系统释放要处理，不承诺低电量时必然常亮。页面没有能力替平板设充电上限或点亮已黑屏；Fully Kiosk 仅后续设备运维选项，不加控制 UI。

iPhone Safari 中显示的地址栏和底部浏览器工具栏属于浏览器界面，网页无法可靠地通过 CSS/JS 隐藏。厨房主体使用文档纵向滚动（容器不建立独立滚动视口）。普通 Safari 的工具栏可能随滚动收起；但从主屏幕启动后进入厨房出现带关闭按钮的浏览器窗口，应排查安装范围，而不能只归因于滚动。开发和生产 Manifest 均明确使用根路径作为启动地址与 scope，覆盖 `/kitchen`；开发不注册 Service Worker。旧入口需要重新添加才能验证新安装信息，操作与 HTTP/HTTPS 限制见[启动指南](../../development/SETUP.md)。系统状态栏等系统界面仍由 iOS 管理，独立应用导航效果尚需 iPhone 真机验收。

## 6. 验收

当前菜的长食材、5000字单步骤和tips均可纵向滚动到达，不显示分页或裁切；10道长菜名菜单可展开；横竖切换不丢文字。双击不触发浏览器放大，同时保留捏合缩放。离开厨房再回来保持滚动位置；关闭常亮提醒后再次进入不重复显示。相同轮询不重绘；改菜内容能更新；旧完成不清新菜单；写入失败不显示成功。HTTPS真机常亮/释放、后台返回、低电量和不支持的浏览器均验收，手机不收到通知。
