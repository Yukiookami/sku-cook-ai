# S14 发送采购清单

状态：已实现共享弹层；独立库/模拟 Todo 传输与组件测试覆盖。本机开发库采购迁移已在用户确认备份并授权后应用；两端实际部署联调未验收。无独立 PNG，沿用 COMMON 奶油 Memo 组件，不宣称按设计图还原。

## 入口与预览

- S02 详情底部“发送采购清单”，携带当前目标份数。
- S01 多选底栏“发送采购清单”，默认各菜原份数；可先进入厨房发送弹层调份数，再对“本次选择”发采购。
- S07 为本次选择或厨房当前菜单发采购，使用相应份数；不改变菜单、不标记做过。
- S01 更多“采购发送记录 / 重试”，无选择时也可恢复最近 20 批已持久化记录。

调用 A34 从服务端读取有归属校验的菜谱/食材预览，展示菜名、目标人份、原始来源、数量与单位。只合并相同名称、相同单位且精确数值明确、无不同备注的项；按 shared 份数规则换算，近似值加“约”不再自动合并。适量、少许、范围和分数保留；不换单位、不强制同义词合并。

可取消勾选已有食材、调整数量文字、修改标题（默认“做菜采购清单”）及选择采购日期（可留空）。日期通过主题化日历对话框选择，确认后才更新；取消不修改当前值，已选日期可清除。数量修改不改原来源；空清单禁用发送。没有食材、预览失败、未启用或非绑定用户明确提示，不假成功。

采购弹层的内容区仅纵向滚动，长来源文本折行，不允许内容横向溢出或横向触摸滚动；标题与日期表单和后续菜谱卡片之间保留明确间距。

## 确认、恢复和新采购

确认生成新 UUID，一次冻结完整快照并先调用 A37 保存，再 A38 发送。发送中只按钮显示状态，禁止重复点击与关闭。快照冻结后编辑禁用；断网/响应丢失明确可能已送达，保留本地会话恢复草稿和服务端记录，按钮“重试原采购批次”。重开不静默抓新菜单替换旧批次。

相同账号的 sessionStorage 保存当前待核对的确认快照，以处理 A37 响应丢失；不跨账号恢复。存储不可用明确警告，已保存批次可从最近采购找回。本地损坏草稿不自动丢弃并新建。

“修改并明确新建采购”使用共用确认弹窗，说明原采购可能已送达且不会撤销；确认后才释放本地恢复草稿、重读当前选择，并在下次确认时生成新 ID。Todo 内容冲突禁止重试为另一 ID，不以新采购按钮伪装错误修复。

成功后只显示简短的“采购清单已发送”提示，不展示直达Todo网页的链接：该链接不能保证唤起用户桌面安装的PWA，可能会打开浏览器。不同步Todo勾选，不自动更改厨房、历史或其他应用。

发送结束自动将弹层内部滚回顶部展示成功/失败结果；成功卡接收键盘焦点，避免用户编辑底部食材后看不到回执。弹层打开聚焦关闭按钮、Tab限制在弹层内、Escape可关闭（发送/确认期间禁止），关闭恢复原入口焦点。

## 验收

预览/份数/来源、排除全部、编辑数量日期、权限拒绝、失败保留、双击去重、超时后原 ID 原内容重试、重开恢复、冲突不换 ID、新采购取消及成功提示不含网页链接。浏览器实际 CSS 320px/390px 已检查两枚底栏按钮无溢出、长内容/列表末尾可滚动到达；390px下模拟Todo成功回执完整可见且聚焦。真机安全区、横向触摸及实际Todo接收结果仍待验收。
