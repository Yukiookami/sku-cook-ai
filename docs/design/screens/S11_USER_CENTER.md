# S11 用户中心

状态：Web、shared、API源码已实现，mock API 与组件行为测试覆盖；真实数据库、浏览器及真机验收待执行。没有独立设计图，本次不更新PNG或提示词。

## 1. 入口与用户范围

- 路由 `/account/profile`，名称 `user-center`，复用全局会话守卫。
- 首页“更多”内的 AccountMenu 通过“用户中心”进入，其他页面不显示账号操作入口。未登录跳转 S10，登录后返回本站目标地址；401沿用全局清理和导航。
- PageHeader 标题“用户中心”，返回按钮导航菜谱一览；展示当前用户名，无用户ID编辑或数据转移。
- 展示当前邮箱，旧账号null显示“未设置（仍可用用户名登录）”；此次不提供修改邮箱或邮箱验证。

## 2. 表单与交互

两个独立表单，分别调用 [A24](../apis/A24_AUTH_USERNAME_PATCH.md) / [A25](../apis/A25_AUTH_PASSWORD_PUT.md)，不合并发送。

| 表单   | 字段与校验                                                         | 提交成功                                         | 失败                                                         |
| ------ | ------------------------------------------------------------------ | ------------------------------------------------ | ------------------------------------------------------------ |
| 用户名 | 3～32位，英文字母开头，仅ASCII字母/数字/下划线；保留大小写，不trim | 更新 currentAccount 和输入框，提示“用户名已更新” | 409账号名已占用或其他错误就地展示，保留输入                  |
| 密码   | 当前密码、新密码，各8～128位且不能全为空白；不trim                 | 更新 currentAccount，清空两项密码，提示会话保持  | 当前密码错误、并发修改、网络或服务失败就地展示，保留两项输入 |

密码校验通过后弹[COMMON](../COMMON.md)的 Memo 共用确认组件：“确定使用新密码吗？现有登录会话将保持不变。”按钮为“确认修改 / 取消”。取消、关闭不发请求，不清空输入，不当作业务错误。

确认等待及任一提交期间两个表单均禁用，阻止重复提交和并行写入。未通过本地shared校验不发请求；服务端仍独立校验。请求不自动重试，不保存密码到浏览器存储或日志。修改保留用户ID、业务归属以及当前和其他设备会话。

## 3. 视觉与可访问性

无独立图，复用 COMMON 奶油黄 Memo、PageHeader、paper-card、既有account-page/account-form样式。手机单列；各卡片标题、字段标签、中文规则与错误可读；输入控件16px、至少50px高。延用S10的100svh及关闭文档平滑滚动，保留正常页面滚动，不锁键盘视口。密码使用type=password及current-password/new-password autocomplete。

状态使用role=status，错误role=alert和aria-describedby；确认框默认聚焦取消，Escape取消、Tab在按钮间循环，关闭恢复焦点。软键盘及iPhone表现仍需真机验收，不能以组件测试替代。

## 4. 验收

- 菜谱等页菜单入口、直接访问鉴权、返回菜谱导航均可达。
- 非法输入不请求，冲突/当前密码错误保留输入及可重试；取消不写入。
- 确认及请求中不重复提交；成功菜单用户名同步、密码字段清空。
- 用户身份只取服务端会话；账户更新不改变数据归属，不撤销会话。
- 已有自动化测试覆盖以上行为；数据库约束/事务及真机尚未集成验收。
