# S10 账号登录与会话设计书

状态：Web 页面、全局会话守卫与业务 API 401 处理已实现；账号接口按 shared Schema 接入。注册、登录、会话保持和退出仍需服务端 HTTP 集成验收。路由 `/account`；`mode=register` 切换开放注册表单。

## 1. 目的与访问控制

为家庭成员提供开放注册、登录、保持会话和主动退出 / 切换账号。所有菜谱、做饭历史及厨房业务页面均须有有效服务端会话；未登录访问业务页先检查会话，再导航至账号页。登录成功后返回用户原本访问的站内地址，直接打开的外部地址不接受为跳转目标。

技术联通页 `/health-check` 与账号页可公开访问。首页 `/` 仍重定向到菜谱一览，因此未登录时会进入账号页。退出成功后清除当前前端用户状态并明确回到登录表单，允许下一位家庭成员登录。

用户名按服务端大小写不敏感唯一规则验证；页面不改变输入大小写，成功后按服务端返回的用户名显示。首用户为 Sku001，注册不改变既有菜谱和厨房数据的归属。

## 2. 页面与流程

```text
菜谱 / 历史 / 厨房 → 检查 GET 会话 → 有效：继续；401：账号登录
登录表单 ⇄ 开放注册表单 → 成功：返回原站内地址（默认菜谱一览）
首页更多 → 账号操作 → 退出 → 登录页 → 可登录其他账号
```

- 登录与注册在同一画面互切；表单保留当前用户名输入。登录“用户名或邮箱”提交 `username`、`password`；注册另需 `email`，仅校验格式、不发送验证邮件。
- 两种操作提交期间禁用表单与切换入口，防止重复请求；失败时保留输入并在表单旁显示可读错误，服务端错误优先使用其公开错误消息，不展示堆栈或内部响应。
- 密码使用遮蔽输入并提供恰当的 autocomplete 提示，长度为 8–128 字符。页面不保存认证凭据到 localStorage / sessionStorage。
- 仅首页更多可见账号操作；超级管理员另显示[S12管理员页面](S12_ADMIN_USERS.md)入口，普通用户不显示。菜单提供“退出并切换账号”，DELETE成功后导航登录页。
- 退出请求失败时保留已登录状态、显示错误并允许重试，不谎称退出成功。
- 全局会话检查失败（非401网络或服务错误）不当作未登录或已登录放行；账号页显示可理解的检查失败说明，仍可重试登录。

## 3. API 与会话

- 注册请求 `{username,email,password}`、登录请求 `{username,password}`（用户名或邮箱）；成功返回 `{user:{id,username,email,isSuperAdmin}}`，服务端设置HttpOnly Cookie。既有空邮箱账号仍可用户名登录。
- `GET /api/auth/session`：成功返回相同用户响应形状；401 表示未登录。
- `DELETE /api/auth/session`：成功返回 204。
- Axios 请求携带 cookie；凭据只由浏览器按 Cookie 安全属性管理，前端不读取、不复制、不自行续期。
- 服务端会话不因空闲过期；持久 Cookie 设为 10 年并在认证请求时滚动续期，浏览器策略或用户清除 Cookie 仍可能结束本机登录状态。业务 API 的 401 响应清除前端会话并导航到账号登录入口，不能继续展示为已认证页面。
- 请求分别使用shared `LoginRequestSchema` / `RegisterRequestSchema`；响应使用 `AuthResponseSchema` / `AuthUserSchema`，不重复声明Contract。

## 4. 画面状态

| 状态                  | 展示与行为                                                           |
| --------------------- | -------------------------------------------------------------------- |
| 登录初始              | 奶油黄便签风格；用户名、密码输入及登录主按钮，提供注册切换入口       |
| 注册初始              | 相同表单布局与字段；明确“创建账号”，可返回登录                       |
| 提交中                | 禁止重复提交，按钮显示对应进行状态，保留字段                         |
| 输入 / 服务端校验失败 | 就地显示可读错误，不清空用户名，不隐藏或吞掉服务端业务失败           |
| 网络 / 服务端失败     | 显示可理解的失败和重试入口；不假报成功                               |
| 会话检查中            | 保护目标业务路由，不短暂展示业务内容                                 |
| 未登录 / 会话401      | 导航账号登录页；登录后返回原站内路径                                 |
| 会话检查网络失败      | 不进入受保护页面；登录页显示“无法确认会话”类提示，允许重新提交登录   |
| 已登录                | 首页“更多”显示当前用户名、用户中心与退出入口；其他页面不显示账号菜单 |
| 退出中                | 禁止重复退出；DELETE 204 后结束本地会话，401 按会话已失效处理        |
| 退出失败              | 留在当前账号状态，显示错误并可重试                                   |

## 5. 视觉与可访问性

账号操作集中在首页“更多”，其中“用户中心”入口导航至受保护的 `/account/profile`，交互见 [S11 用户中心](S11_USER_CENTER.md)。通用子页标题和厨房显示页不显示头像或账号菜单，切换账号先返回首页操作。原 `/account` 登录注册及退出流程不变。用户名修改成功后共用会话状态立即更新菜单显示，其他设备下次认证请求读取当前用户名。

无独立设计图；沿用 [COMMON](../COMMON.md) 的奶油黄 Memo 规范：`#FFFDF8` 页面底色、`#FFF4C2` 浅黄、`#FFE28A` 主按钮、白色圆角卡片、深棕文字。手机单栏，最大宽度约 480px；标题 24～28px，正文 16px，页面边距约 20px，主操作高度至少 48px。

账号页及页面背景使用稳定的小视口最小高度（100svh），用户名和密码输入字号明确为16px，避免 iOS 聚焦自动放大。账号页关闭文档平滑滚动，避免软键盘出现时自动定位输入框产生额外滑动动画；保留正常滚动，不锁定页面或阻止浏览器将输入框移到键盘上方。软键盘聚焦与收起的具体表现需 iPhone 真机验收。

用户名和密码各有可见标签；登录 / 注册切换、提交、账号菜单和退出均是带文字的键盘可操作控件。字段错误使用关联说明及 `aria-describedby`；请求状态以 `role=status`，错误以 `role=alert` 呈现。不得只靠颜色表达状态。

## 6. 验收

- 未登录刷新或直接访问每个业务路由均先检查服务端会话；401进入登录，不闪现业务内容；登录后回到站内目标地址。
- 有会话时刷新仍显示业务并保留服务端返回用户名；前端不使用本地凭据替代服务端校验。
- 登录与注册可互切；提交失败保留输入并展示可理解错误；提交中不允许重复发送。
- 注册响应通过 shared Schema 校验并进入登录态；用户名显示保留用户提交大小写；唯一性冲突由服务端反馈。
- 仅首页“更多”提供账号操作；通用子页标题和厨房页不显示账号入口。首页退出收到DELETE 204后到登录页；再次登录可以切换用户。
- GET session 401 与业务 API 401 均不继续呈现受保护内容；网络错误不能伪装成401。
- Mock API 行为测试覆盖守卫、登录、注册、退出及401。服务端数据库及真实浏览器持久 Cookie、跨浏览器续期仍需集成 / 真机验收。
